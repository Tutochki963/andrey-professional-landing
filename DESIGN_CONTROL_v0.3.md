# DESIGN CONTROL v0.3 — Andrey Professional Landing

**Статус:** design-control specification before next visual implementation  
**Цель:** превратить текущую аккуратную инженерную страницу в зрелое профессиональное портфолио с контролируемым WOW-эффектом, психологической мягкостью, визуальной гармонией и доказательностью.

---

## 1. Поведенческая модель посетителя

Посетитель не читает страницу линейно. Он сначала сканирует её короткими визуальными рывками и лишь потом решает, стоит ли читать.

### Первые 3 секунды

Мозг должен уловить:

- человек зрелый и профессиональный;
- тема — бизнес + AI + automation;
- визуально это не шаблон и не киберпанк;
- есть собственная система / метод;
- хочется посмотреть дальше.

### 3–10 секунд

Посетитель должен найти три якоря:

1. основное обещание;
2. визуальный символ / система;
3. доказательство компетентности.

### 10–30 секунд

Он должен быстро считать:

- карьерную зрелость;
- подход Diagnose → Design → Implement;
- реальные AI-work units;
- архитектуру AI-STUDIO;
- способ связаться.

Отсюда правило: **страница проектируется не как текст, а как последовательность визуальных решений внимания.**

---

## 2. Психологический тон

Целевое ощущение:

**спокойная компетентность + технологичность + человеческая надёжность + инженерная точность**.

Нельзя:

- cyber-security mood;
- кислотные акценты;
- чёрный вакуум;
- robotic coldness;
- агрессивный startup typography;
- декоративная сложность без смысла.

WOW для взрослой аудитории должен идти не от яркости, а от:

- неожиданно чистой композиции;
- глубины;
- качественной типографики;
- движения смысла;
- брендингового символа;
- аккуратных микроанимаций;
- доказательной визуализации.

---

## 3. Главный визуальный символ — Cyber Sun

Использовать существующую эмблему AI-STUDIO как **брендовый визуальный якорь**.

Не использовать её в текущем белом квадрате.

### Требуемая версия

Нужен public-web вариант:

- прозрачный фон;
- сохранена узнаваемая круговая конструкция;
- navy / blue-grey основа;
- cyan и magenta заметно приглушить;
- добавить немного sand / warm highlight;
- убрать ощущение яркого логотипа SaaS;
- сохранить технологическую сложность внутри центрального ядра.

### Место в hero

Cyber Sun должен стать частью правой композиции, а не отдельной картинкой:

- размер ориентировочно 180–240px;
- частично пересекается с Working Path;
- орбитальные дуги могут визуально продолжать route lines;
- opacity / lighting спокойные;
- лёгкое медленное breathing / rotation только для внешнего кольца, если motion не отвлекает.

### Header

Миниатюрная версия 22–26px рядом с `ANDREY G.` допустима и желательна.

Это свяжет персональный бренд и AI-STUDIO, не превращая header в корпоративный логотип.

---

## 4. Android — осторожно

Полноценный «робот в hero» легко превращает сайт в клише AI-лендинга.

Поэтому Android не должен быть главным объектом первой версии v0.3.

Если использовать:

- не humanoid stock robot;
- не лицо крупным планом;
- не sci-fi character;
- лучше абстрактный фрагмент человекоподобного интерфейса / силуэт / инженерный манекен;
- opacity низкая;
- роль — второй план, поддерживающий Human + AI тему.

Приоритет: **Cyber Sun сначала. Android — только если после hero QA останется визуальная пустота.**

## 5. Hero — композиционный контроль

### Сетка

Desktop: 12 колонок.

- left copy: 6.5–7 колонок;
- right visual system: 5–5.5 колонок.

### Иерархия

1. Cyber Sun / Working Path вместе формируют визуальный магнит справа.
2. Main statement — главный смысловой магнит слева.
3. Short support copy.
4. CTA.
5. Proof strip должен визуально примыкать к hero.

### Заголовок

Текущий размер уже ближе к норме, но нужно контролировать строки:

EN target:

`I turn business problems`  
`into practical AI-enabled`  
`systems.`

Максимум 3–4 строки.

Font weight: 500–560 визуально, не 700+.

### Симметрия

Не геометрическая зеркальность, а **оптический баланс масс**:

- если слева 650px текста, справа visual mass должна быть сопоставимой;
- card не должна висеть отдельно;
- Cyber Sun должен уравновешивать большую белую типографику.

---

## 6. Типографическая система

Основной переход: от «технологического headline» к **editorial business-tech typography**.

### Display

Предпочтительный системный stack:

`Aptos Display, Segoe UI Variable Display, Segoe UI, system-ui`

### Body

`Aptos, Segoe UI Variable Text, Segoe UI, system-ui`

### Правила

- h1 weight 500–550;
- h2 weight 480–540;
- h3 weight 600–650;
- body 400–450;
- uppercase использовать только для micro-labels;
- уменьшить количество uppercase labels минимум на треть;
- line-height h1 ≈ 1.02–1.07;
- line-height h2 ≈ 1.05–1.10.

Главная цель: текст должен быть дорогим и спокойным, не «кричащим».

## 8. Depth / объём

Объём — обязательный слой v0.3.

Использовать три уровня:

### Level 0 — Page plane

Тёплый graphite + очень мягкие световые поля.

### Level 1 — Content surfaces

Proof, evidence, architecture surfaces:

- +2–4% brightness;
- 1px soft border;
- top highlight;
- мягкая тень вниз;
- без glow.

### Level 2 — Interactive focus

Hover / active:

- +3–5px translateY максимум;
- border слегка теплеет;
- shadow становится чуть шире;
- внутренний highlight усиливается.

---

## 9. Motion — рациональная динамика

Motion должен подтверждать смысл.

### Buttons

Hover 180–260ms:

- background gently lifts;
- border changes toward sand / blue-grey;
- soft shadow;
- translateY(-2px);
- arrow moves 2–3px вправо.

### Cyber Sun

Если используется animation:

- внешнее кольцо: 24–40 sec linear rotation;
- центральное ядро статично;
- hover может слегка усилить depth;
- prefers-reduced-motion отключает движение.

### Working Path

При hover над hero visual:

- nodes последовательно получают soft highlight;
- Result остаётся тёплой финальной точкой.

Никаких looping flashing effects.

---

## 10. Track Record — harmony control

Сейчас структура правильная, но требует более визуального narrative.

Для каждого этапа отдельный визуальный proof:

- Wrigley → `73% → 92%`;
- Mars → `~70 people / 2 teams / 2 distributors`;
- Entrepreneurship → `2016 → present`;
- Applied AI → встроенный warm layer.

Timeline line должна быть тоньше текста и не конкурировать с заголовком.

---

## 11. Approach — не таблица

Сохранить 3 этапа, но убрать ощущение grid/table.

Рекомендуемая композиция:

- три крупных step numbers;
- между ними directional line;
- текст свободно расположен под узлом;
- вертикальные divider убрать или ослабить на 70%;
- output сделать вторичным уровнем.

---

## 12. Selected Work — главный WOW после hero

Это место, где посетитель должен перейти от «интересно» к «это серьёзная работа».

Требования:

- один кейс на один визуальный ритм;
- evidence slot должен содержать настоящую schematic illustration, а не пустые boxes;
- left/right баланс 50/50 или 45/55;
- кейсы могут иметь разную schematic pattern;
- status badge небольшой;
- title и problem не должны конкурировать.

Порядок визуального чтения:

`CASE → TITLE → PROBLEM → VISUAL EVIDENCE → ROLE → STATUS`

## 13. AI-STUDIO map

Текущая логика зон удачна, но оформление ещё напоминает dashboard.

Нужно:

- заменить тяжёлые vertical borders на мягкие tonal zones;
- зоны различать background depth, а не линиями;
- rails сделать тонкими горизонтальными bands;
- Human Decision оформить как финальный warm gate;
- Cyber Sun может повторяться здесь маленьким watermark / seal как sign of system ownership.

## 14. Professional Foundation

Это supporting section, не hero №2.

- headline уменьшить ещё на 10–15%;
- education и skill groups сделать компактнее;
- больше воздуха, меньше линий;
- не позволять этому разделу визуально конкурировать с Selected Work.

## 15. Contact — человеческое приглашение

Contact должен психологически переводить посетителя из анализа в действие.

Сделать фон немного теплее остальной страницы.

Primary row:

- Discuss a project
- Talk about a role
- Partnership

Real channels:

- Email
- LinkedIn
- Telegram
- GitHub

Hover должен быть мягким и заметным.

После появления публичных адресов убрать техническую строку о том, что ссылки будут активированы позже.

---

## 16. Контроль симметрии и гармонии

Перед каждым релизом проверять desktop 1280px:

- одинаковые внешние поля слева / справа;
- optical center hero;
- не более одной dominant mass на половину экрана;
- равновесие светлых и тёмных областей;
- одинаковые radius-family;
- одинаковая логика shadows;
- линии не должны заканчиваться случайно;
- соседние секции не должны иметь одинаковую высоту без причины;
- пустота должна быть намеренной.

### Контрольный вопрос

Если убрать весь текст и смотреть только на светлые / тёмные массы, остаётся ли композиция сбалансированной?

Если нет — дизайн не готов.

## 18. Критерий качества v0.3

Посетитель должен почувствовать не «здесь умеют рисовать AI-интерфейсы», а:

Это и есть нужный WOW-эффект.
